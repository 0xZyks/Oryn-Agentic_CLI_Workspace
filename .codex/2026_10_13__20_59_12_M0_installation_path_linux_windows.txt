DEMANDE

Ajouter un petit script SH pour installer Oryn dans le PATH sous Linux,
et un équivalent Windows si possible.

RÉSULTAT ET FICHIERS

- scripts/install-linux.sh : script Bash exécutable, installation utilisateur.
  Publication Release incluant le runtime .NET ; détection Linux x64/ARM64.
  Fichiers conservés ensemble dans ~/.local/share/oryn ; lien ~/.local/bin/oryn.
  PATH ajouté à .profile, .bashrc, .zshrc et aux profils de login Bash existants,
  sans répéter la même ligne. La commande export affichée active le PATH dans
  le terminal courant ; le script enfant ne peut pas modifier son parent.
  Options --prefix, --runtime, --no-path et --help. Les cibles musl/Alpine
  nécessitent --runtime linux-musl-x64 ou linux-musl-arm64.
  Le script refuse de remplacer un autre launcher ; une publication échouée
  ne remplace pas les fichiers installés. Pas de sudo requis.
- scripts/install-windows.ps1 : publication Release autonome pour win-x64
  ou win-arm64 ; installation dans %LOCALAPPDATA%\Oryn. Ajout au PATH utilisateur
  persistant et au PATH du processus PowerShell courant, sans dupliquer l'entrée
  ni copier le PATH machine. Options -InstallDir, -Runtime et -NoPath.
  Aucun changement global de politique PowerShell ni privilège admin requis.
- README.md : commandes Linux/Windows, destinations, options, prérequis,
  activation du PATH, mise à jour et limites de validation.
- Ce log de passation.

Les scripts compilent depuis la racine du dépôt afin de respecter global.json,
même s'ils sont invoqués ailleurs. Ils publient d'abord dans un dossier temporaire,
puis copient l'ensemble des fichiers. Réexécuter le script après mise à jour des
sources, Oryn fermé. Le SDK .NET 10 compatible avec global.json et l'accès aux
packages NuGet/runtime sont requis pour compiler. Le runtime est inclus dans
la publication destinée à la machine cible ; conserver ses fichiers associés.
