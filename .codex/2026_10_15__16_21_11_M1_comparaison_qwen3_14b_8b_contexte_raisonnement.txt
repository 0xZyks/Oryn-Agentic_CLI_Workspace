Qualité : observations limitées
Les deux modèles réussissent extraction de clé et calcul, mais répondent à tort A=OUI,B=OUI pour default interface method C# (attendu A=NON,B=OUI). Compilation temporaire .NET10 dans /tmp/oryn-m1-interface-probe : appel direct new C().M() rejeté CS1061 ; version avec seulement ((I)new C()).M() compilée sans erreur. Les deux réponses sur fragments tardifs ne fournissent pas clairement une protection par identité de génération avant application à B (revue humaine, pas score automatique).
Aucun gain qualité14B établi par ce très petit ensemble. Maintenir candidats et évaluer sur questions projet représentatives avant choix. Pas d'essai8BQ8/14BQ5/32B ou contexte16384.

Vérifications et incident corrigé
Smokes14B4096,14B8192extended et8B8192extended finaux réussis : streaming, fin SSE, annulation par déconnexion, idle~0.10s et compteur stable, nouvelle requête, malformedHTTP400, fermeture exit0, GPU libéré, backend inaccessible ensuite. Tous serveurs arrêtés.
Premier8Bextended interrompu SIGBUS(-7) pendant que setup réextrayait les .so en cours d'utilisation ; ne pas confondre avec échec modèle. Rapport/log préservés sous artifacts/m1/8b-extended-8192-interrupted.*. Correction : verrou flock partagé conservé à travers exec pour run.py, exclusif non bloquant pour setup.py. Vérifié contre vrai serveur14B actif : setup refuse avant extraction ; sens inverse vérifié avec verrou exclusif de setup : run refuse. Host prompt cache borné à0 pour éviter snapshotsRAM implicites dans ces benchmarks. Résultats finaux issus de relance sans collision.
Python py_compile, --help des3scripts et git diff --check réussis. Aucun build de solution/app Oryn ; seuls builds temporaires pour preuveC# (un échec attendu, un succès). ValidationsM0 historiques non relancées. Aucun test UI ou autreOS.
